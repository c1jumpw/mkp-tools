Sign in & install

Everyday

Open DayForge in any browser and sign in with your email and password. You stay signed in on that device until you sign out.

Put it on your home screen

DayForge works like an app once it's on your home screen: full screen, its own icon, no browser bars.

  1. iPhone or iPad: open DayForge in Safari, tap Share, then Add to Home Screen.
  2. Android: open it in Chrome, tap ⋮, then Add to Home screen (or Install app).
  3. Computer: bookmark it, or in Chrome use the install icon in the address bar.
Good to knowEverything you add is saved to your account, not to the device, so your phone and computer always show the same plan. The only thing each device remembers on its own is light or dark mode.

06

Repeats & routines

Everyday

Repeating tasks

In a task's details, set Repeats to Daily or Weekly on selected days. The task then shows on every matching day with a ↻, and ticking it done on one day doesn't tick off the others.

Routines

A routine is a saved set of tasks, like a morning routine or a gym day. Applying it copies its tasks onto the day you're looking at, already timed.

TipPick the day first (Forecast or the ‹ › arrows), then open Routines and tap Apply to day.

08

Voice notes & files

Everyday

Record a voice note on a task

  1. Open a saved task. (New tasks need saving first, so the recording has somewhere to go.)
  2. Tap Record voice note and allow the microphone. A timer shows Recording… while you speak; tap Stop when done.
  3. Where the browser supports it, a live transcript appears. Tap Copy transcript to paste it into the task's notes.
  4. Tap Download audio (.wav) to keep the recording as a standard audio file.
On iPhoneLive transcription often doesn't start in Safari. The recording is still saved; you'll see a message saying transcription couldn't start.

Attach files

  1. In a task, tap + Add file; in a note, tap Files ▾. Any file type works.
  2. Give it a label if you like (Label this file). Photos are resized before upload to save space.
  3. Tap a photo to view it full size, or any other file to download it. The ✕ badge deletes it after you confirm.

A2

Publish an update

Admin
  1. Commit the change to GitHub on the main branch of c1jumpw/mkp-tools, inside the dayforge folder.
  2. Vercel builds and publishes it automatically, usually within a minute or two. The project's Deployments page shows progress.
  3. If the update includes a database change, run its file in Supabase (A3). Do this before or right after publishing.
  4. On each device, open ⋮ › Refresh app so it loads the new version.
Undo a bad releaseIn Vercel › Deployments, pick the last good deployment and use Instant Rollback (or Promote to Production). Your data in Supabase isn't affected.
A3

Database updates

Admin

Some features need a one-time database change, shipped as a numbered .sql file in dayforge/supabase/migrations. Run each one once, in order.

  1. Open Supabase and the DayForge project.
  2. Go to SQL Editor › New query.
  3. Paste the whole file and tap Run. "Success. No rows returned" means it worked.
FileWhat it adds
schema.sqlThe starting tables, for a brand-new project only
002_voice_notes.sqlVoice notes on tasks
003_notes.sqlThe Notes notepad
004_entry_images.sqlPhotos on tasks and notes
005_generic_attachments.sqlAny file type as an attachment
006_note_colors.sqlNote colors
007_note_pinning.sqlPinning notes
008_note_labels.sqlNote labels and label filters. Safe to run more than once
Signs one is missingNotes shows "Labels need a one-time database update (migration 008)", or a feature reports it couldn't save. Run the matching file, then Refresh app.
A4

Accounts & security

Admin
  • Private by account. Database rules let each account read and change only its own rows. Voice notes and files sit in private storage.
  • The key inside the app is meant to be public. Supabase's "anon" key only works within those rules. Never put the service_role key in the app or in chat.
  • Change email or password from ⋮ › Account settings.
  • Forgot the password? In Supabase › Authentication › Users, open the user and send a password recovery email.
  • Turn off new sign-ups. The sign-in screen has a "Create your account" link. Once your account exists, switch off Allow new users to sign up in Supabase › Authentication › Sign In / Providers. New accounts couldn't see your data anyway, but this keeps the app to you alone.

A6

Keeping help current

Admin

This guide and the getting-started tour rebuild themselves. You only write the What's new note.

  1. Push an update to the DayForge folder on GitHub as usual.
  2. An automatic job (GitHub › Actions › "Refresh guides and tours") opens the app with example data, retakes every screenshot, rebuilds this guide and the tour, and saves them back to GitHub. It takes a few minutes; then the live app shows the new pictures.
  3. Say what changed by adding an entry to the top of dayforge/CHANGELOG.md: a ## date · title line and a few - lines. Everyone sees it once, as What's new, the next time they open the app.
If the job failsGitHub emails you when a numbered marker can't find its button, which means a screen changed. The log lists which picture and marker. Update the screenshot steps in guides/ and the matching text, then push again. Until then the guide keeps its previous pictures.

Everything the job uses lives in the guides/ folder: the screenshot steps, the guide text (guide.src.html), the tour slides (tour.json) and a README.
